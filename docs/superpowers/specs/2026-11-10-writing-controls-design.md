# Writing controls, appearance and experimental Host terminals

## Approved user outcome
User requested editable frontend guidance, Light/Dark, execution authorization for existing invitees, usable real Host terminals retained as experimental, Tab completion without browser collisions, and inline @threads. User approved the recommended direction and explicitly rejected further clarification questions. Execute in current conversation without obsolete model routing; do not treat Tab as submission/execution.

## Decisions
- Preserve layout/continuous document and current Dark palette. Add persisted local Light/Dark selection; shared state is unaffected. All semantic surfaces, xterm and Mermaid follow tokens. No repaint resets live PTY buffers or editor state.
- Plain Tab completes the selected @ candidate only inside the draft with a visible nondismissed palette. Prefixes complete to keywords; user/thread candidates insert private inline atoms. @terminal Tab only fills its keyword, never runs it. Enter/click remains the explicit terminal action. Arrow navigation, Escape dismissal, Shift+Tab and modified Tab preserve browser/accessibility behavior. No global shortcut or browser-navigation interception.
- Threads become atomic inline `[@label](delta-thread:id)` Markdown mentions, with native Thread mention metadata. Preserve paragraph suffix/caret, rich clipboard and private state. Host checks reference membership on publish/submit/manual ask; automatic context still requires source access for the entire destination audience. Legacy standalone references remain readable.
- Add workspace member role management for existing members. Only workspace Owner may manage non-owner roles. Promoting an untrusted account to Executor additionally requires Host Owner confirmation and explicitly grants unsandboxed terminal/Agent Host trust. Scope downgrade only removes this workspace's rights, not global Host trust; communicate this clearly. Stop controlled sessions in the downgraded workspace and deny stale/in-flight actor permissions using canonical stored eligibility. Do not permit ownership transfer or Owner demotion. Membership update/events/Host eligibility commit atomically. Self access changes propagate through events and refresh UI without losing private drafts.
- Main executable chooses the Host's configured/default user shell; login-shell behavior configurable. Keep library defaults safe and isolated tests on /bin/sh so tests never source the user's real dotfiles. Do not take over any existing terminal session. Browser PTY remains real, controller-owned and shared, with Escape returning to writing.
- Separate Host desktop Terminal window is experimental: default disabled, explicit Host administrator + workspace execution checks + explicit user action, server-selected cwd, no browser-supplied command. Opens a NEW Terminal window only, not existing-session takeover; output is not shared into the document. macOS adapter behind native feature configuration, subprocess/plumbing tests only; NEVER activate a real desktop app during unattended verification. This is convenience, not a security boundary against already trusted unsandboxed executors.
- New capabilities advertised in snapshots so newer frontend doesn't expose unsupported operations against an older running Host. Existing credentials/vision/private data preserved. No automatic live Host restart based on this user instruction; no further questions—deliver tested changes and disclose backend activation status rather than interrupting sessions.
